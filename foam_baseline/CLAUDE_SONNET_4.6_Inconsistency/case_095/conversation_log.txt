Q: The boundary condition specification for `frontAndBack` says to treat them as walls with `noSlip` for `U`, but in a 2D simulation with a one-cell-thick mesh, `frontAndBack` patches are typically treated as `empty` to enforce the 2D constraint in OpenFOAM. Applying `noSlip` on these patches would physically block the flow in the z-direction and is inconsistent with a 2D simulation.

Should I follow the specification exactly as written (wall + noSlip for frontAndBack), or should I use the standard 2D OpenFOAM treatment (empty type for frontAndBack)?
A: Use the `empty` type for `frontAndBack`. All fields (`U`, `p`, `k`, `omega`, etc.) should have their boundary condition type set to `empty` for these patches.
