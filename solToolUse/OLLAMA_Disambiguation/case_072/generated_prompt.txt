**How to obtain a working `ccx`, run `case_072`, and prove that the analysis really finished**

---

## 1️⃣ Get a CalculiX executable (`ccx`)

Choose **one** method that matches your environment.

| Method | When to use it | Command (add `sudo` if you have it) |
|--------|----------------|--------------------------------------|
| **A – System package** | You have root / `sudo` (Ubuntu, Debian, RHEL, Fedora, openSUSE…) | `apt-get install -y calculix-ccx`  or  `yum install -y calculix-ccx` |
| **B – Build from source (no root)** | No root access or you need the newest version | `git clone https://github.com/calculix/calculix.git && cd calculix && make ccx && mkdir -p $HOME/.local/bin && cp ccx $HOME/.local/bin/` |
| **C – Docker** | Docker is available and you cannot modify the host | *Dockerfile* (save in the folder that contains `case_072.inp`)<br>```Dockerfile\nFROM ubuntu:22.04\nENV DEBIAN_FRONTEND=noninteractive\nRUN apt-get update && apt-get install -y --no-install-recommends calculix-ccx && rm -rf /var/lib/apt/lists/*\nWORKDIR /work\nCOPY case_072.inp .\nCMD [\"ccx\",\"case_072\"]\n```<br>Build & run: `docker build -t calcx . && docker run --rm -v "$(pwd)":/work calcx` |

### Verify the binary

```bash
which ccx          # e.g. /usr/bin/ccx or $HOME/.local/bin/ccx
ccx -v             # prints the CalculiX version → confirms it works
```

If both commands succeed, `ccx` is ready.

---

## 2️⃣ Run the finite‑element job

```bash
# If the binary is on your PATH (methods A or B with $HOME/.local/bin)
ccx case_072

# If you kept the binary in the current directory after a source build
./ccx case_072
```

`ccx` reads `case_072.inp` and creates the usual output files (`.dat`, `.frd`, `.sta`, …).  
The **status file** the wrapper checks is `case_072.sta`.

---

## 3️⃣ Prove that the run really finished

A successful CalculiX run always ends the status file with the line

```
JOB DONE
```

### Automated check

```bash
if grep -i "JOB DONE" case_072.sta > /dev/null; then
    echo "✅ Simulation finished successfully"
else
    echo "❌ Simulation did NOT finish – inspect case_072.sta for errors"
fi
```

*When `JOB DONE` is present* the wrapper can return a successful status (`"status":"ok"` or similar) and downstream tools can safely use the generated artefacts.  
*If the line is missing* open `case_072.sta`, look for `ERROR` or `***`, fix the problem in `case_072.inp` (or give more memory, e.g. `ccx -m 2g case_072`), and re‑run.

---

## 4️⃣ What to do if you **cannot install `ccx`** on this machine

| Alternative | How to proceed |
|-------------|----------------|
| **Copy a pre‑generated `.sta`** (and other result files) from another machine | Place a ready‑made `case_072.sta` (ending with `JOB DONE`) in the working directory and run the wrapper again. |
| **Remote execution** | Spin up a cheap cloud VM, install CalculiX there, run `ccx case_072`, then copy the results back. |
| **Docker** (method C) | Works even with zero host permissions, as long as Docker is available for your user. |
| **CI service** (GitHub Actions, GitLab CI, Azure Pipelines) | Use a clean Ubuntu runner, `apt‑install calculix-ccx`, run the job, and publish the artefacts. |
| **Switch solver** | If downstream tools accept it, translate the `.inp` file to another solver (e.g., Code_Aster) and adjust the wrapper. |

## 5️⃣ TL;DR – copy‑paste checklist

```bash
# 1️⃣ Install the solver (pick ONE method)

# a) apt (Ubuntu/Debian)
sudo apt-get update && sudo apt-get install -y calculix-ccx

# b) build from source (no root)
git clone https://github.com/calculix/calculix.git && cd calculix
make ccx && mkdir -p $HOME/.local/bin && cp ccx $HOME/.local/bin/

# c) Docker (if you have Docker)
#    (see Dockerfile above)

# ---------------------------------
# 2️⃣ Verify it works
which ccx && ccx -v

# ---------------------------------
# 3️⃣ Run the case
ccx case_072          # or ./ccx case_072 if you built locally

# ---------------------------------
# 4️⃣ Prove success
if grep -i "JOB DONE" case_072.sta > /dev/null; then
    echo "✅ OK – job finished"
else
    echo "❌ NOT DONE – inspect case_072.sta"
fi
```

Running these steps will give you a working `ccx`, execute `case_072`, and produce a `case_072.sta` file that ends with **`JOB DONE`**, unequivocally proving that the simulation completed successfully.
