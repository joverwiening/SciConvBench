**Abaqus *.inp* – Copy‑and‑paste ready cheat‑sheet for a **distance‑type MPC** (keeps the Euclidean distance between two nodes constant)**  

> **Only the node numbers (and, optionally, the `USEREL` flag) need to be edited – everything else can stay exactly as shown.**  

---  

## 1. Keyword syntax  

```text
*MPC, TYPE=DISTANCE, USEREL=YES|NO
reference‑node , slave‑node
```

| Item | Required? | What it does |
|------|-----------|--------------|
| `*MPC` | **yes** | Starts a Multi‑Point Constraint definition. |
| `TYPE=DISTANCE` | **yes** | Enforces a **constant Euclidean distance** between the two nodes. |
| `USEREL=YES` | optional | Re‑evaluate the line direction **at every increment** from the **current** coordinates. Use when the reference node moves or when large rotations are expected. |
| `USEREL=NO` | optional (default) | Use the **original mesh** coordinates to define the line direction. Sufficient for small‑strain, fixed‑reference problems. |
| Data line (`reference‑node , slave‑node`) | **yes** | Two integer node IDs. One line = one independent distance constraint. |
| Additional data lines | optional | Add as many “reference, slave” pairs as you need – each line creates a separate constraint equation. |

> **Tip:** Keep the reference node first, the slave node second. The order only flips the sign of the equation, but a consistent convention makes the file easier to read.  

---  

## 2. Minimal working example (copy‑paste)

```abaqus
*Heading
** Example: keep the distance between node 100 (reference) and node 200 (slave) constant
*Node
100, 0.0, 0.0, 0.0
200, 10.0, 0.0, 0.0
** (other nodes …)

*Element, type=C3D8
...                     (your element connectivity)

** ---------- Distance‑type MPC ----------
*MPC, TYPE=DISTANCE, USEREL=NO   ! change USEREL to YES if the reference node moves
100, 200                         ! 100 = reference node, 200 = slave node
```

*If the reference node is expected to move (or you have large rotations), simply switch the flag:*

```abaqus
*MPC, TYPE=DISTANCE, USEREL=YES
100, 200
```  

---  

## 3. Several constraints in one block  

```abaqus
*MPC, TYPE=DISTANCE, USEREL=NO
100, 200
101, 205
102, 210
...   ! add as many pairs as required
```  

*Each line creates a separate constraint equation; you can list dozens of pairs in the same block.*  

---  

## 4. Common pitfalls & how to avoid them  

| Pitfall | Why it happens | Fix / recommendation |
|---------|----------------|----------------------|
| **Duplicate ties** (same pair already tied by a *Tie*, *Rigid Body*, or another MPC) | Over‑constrains the system → job aborts. | Verify each pair appears **only once** and that no other constraint already links the two nodes. |
| **Reference node moves but `USEREL=NO`** | Direction vector stays fixed to the original mesh, giving an unrealistic constraint after translation/rotation. | Use `USEREL=YES` when the reference node is free to move. |
| **Large rotations** | Fixed direction (`USEREL=NO`) no longer represents the true line between nodes. | Set `USEREL=YES`. |
| **Reference node belongs to a rigid body** | The distance constraint will also restrict the rigid body’s motion, possibly over‑constraining the model. | Choose a reference node **outside** the rigid body, or be sure the added restriction is intended. |
| **Too many distance MPCs** | Each MPC adds one extra equation → longer solve time. | Keep the number of distance constraints to the minimum required for the physics you need. |
| **Wrong node order** | Swapping reference ↔ slave changes the sign of the constraint equation (harmless but confusing). | Keep the intended reference node first, slave node second. |

---  

## 5. Quick pre‑run checklist  

1. **List every node pair** that must stay at a constant distance.  
2. **Choose `USEREL`**  
   * `NO` (default) → direction fixed to original mesh (good for small‑strain, fixed reference).  
   * `YES` → direction recomputed each increment (required for moving reference nodes or large rotations).  
3. **Insert the `*MPC` block** after the *Node*/*Element* sections and **before the first *Step***.  
4. **Write one line per pair** (`reference‑node, slave‑node`).  
5. **Check for conflicts** with other constraints (Tie, Rigid Body, other MPCs).  
6. **Run the analysis** – Abaqus will enforce a constant distance for every listed pair.  

---  

## TL;DR – One‑liner you can drop into any *.inp* file  

```abaqus
*MPC, TYPE=DISTANCE, USEREL=YES   ! or USEREL=NO
refNode1, slaveNode1
refNode2, slaveNode2
...
```  

That’s all you need to keep the Euclidean distance between any two (or many) nodes **constant** in Abaqus. Happy modelling!
