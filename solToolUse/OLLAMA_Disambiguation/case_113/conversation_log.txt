Q: **Using an *MPC* to keep the distance between two nodes constant**

In Abaqus a multi‑point constraint (MPC) of type **DISTANCE** forces the relative motion of a *slave* node along the line that joins it to a *reference* node to be zero.  
Mathematically the constraint is

\[
\bigl(\mathbf{u}_\text{slave}-\mathbf{u}_\text{ref}\bigr)\cdot
\bigl(\mathbf{X}_\text{slave}-\mathbf{X}_\text{ref}\bigr)=0
\]

where **X** are the original nodal coordinates and **u** are the nodal displacements.  
Consequently the Euclidean distance between the two nodes does not change during the analysis.

---

### 1.  What you have to specify

| Keyword option | Meaning |
|----------------|---------|
| `TYPE=DISTANCE` | Choose the distance‑type MPC. |
| `USEREL=YES/NO` (optional) | **YES** – the direction vector is recomputed from the *current* coordinates (useful for large‑deformation problems). **NO** (default) – the direction is taken from the original mesh. |
| Data line | `reference‑node , slave‑node` (both are integer node IDs). |
| Multiple constraints | You can list several “reference, slave” pairs under the same *MPC* block. |

---

### 2.  Minimal input‑file snippet

Below is a self‑contained example that shows how to lock the distance between node **100** and node **200**.  
The same block can be placed anywhere after the *Node* and *Element* definitions and before the first *Step*.

```abaqus
*Heading
** Example: distance constraint between node 100 and node 200
*Node
100, 0.0, 0.0, 0.0
200, 10.0, 0.0, 0.0
** (other nodes …)

*Element, type=C3D8
...                     (your element connectivity)

** -------------------------------------------------
**  Multi‑point constraint: keep the distance constant
** -------------------------------------------------
*MPC, TYPE=DISTANCE, USEREL=NO
100, 200
```

**Explanation**

* `*MPC, TYPE=DISTANCE` tells Abaqus to create a distance‑type MPC.  
* `USEREL=NO` (the default) means the line direction is taken from the original coordinates of nodes 100 and 200.  
* The data line `100, 200` designates node 100 as the *reference* node and node 200 as the *slave* node.  

If you prefer the direction to follow the deformed configuration (e.g., when the reference node itself moves), change the option to `USEREL=YES`:

```abaqus
*MPC, TYPE=DISTANCE, USEREL=YES
100, 200
```

---

### 3.  Adding many distance constraints

When you have many node pairs you do **not** need a separate *MPC* block for each pair.  Simply list them one after another:

```abaqus
*MPC, TYPE=DISTANCE
100, 200
101, 205
102, 210
...
```

Abaqus will generate a separate constraint equation for every line.

---

### 4.  Things to watch out for

| Issue | What to check |
|-------|----------------|
| **Over‑constraining** | Make sure the two nodes are not already tied together by other constraints (e.g., a *Tie* or a *Rigid Body* definition). |
| **Rigid body motion** | If the reference node belongs to a rigid body, the distance constraint will also constrain that rigid body’s motion. |
| **Large rotations** | For very large rotations the original line direction may become inappropriate; use `USEREL=YES` in that case. |
| **Solver type** | Distance MPCs are supported in both static and dynamic analyses; they are treated as linear constraint equations. |

---

### 5.  Quick checklist for your large model

1. Identify the two node IDs that must stay at a fixed distance.  
2. Decide whether the direction should be based on the original mesh (`USEREL=NO`) or on the current configuration (`USEREL=YES`).  
3. Insert a single `*MPC, TYPE=DISTANCE` block (or several blocks if you want different `USEREL` settings).  
4. List the `reference‑node , slave‑node` pairs.  
5. Run the analysis – Abaqus will automatically add the corresponding constraint equations to the global system.

That’s all you need to enforce a distance constraint between any two nodes in a large Abaqus model. Happy modelling!
A: **Using an *MPC* to keep the distance between two nodes constant in Abaqus**  

Below is a compact, step‑by‑step reference that contains everything you need to create a **DISTANCE**‑type multi‑point constraint (MPC).  Copy‑paste the relevant parts into your *.inp* file, adapt the node numbers and options, and you are ready to run.

---

## 1.  What the keyword needs

| Keyword / option | Meaning |
|------------------|---------|
| `*MPC, TYPE=DISTANCE` | Selects the distance‑type MPC (the only type that enforces a constant Euclidean distance). |
| `USEREL=YES` | The direction vector is recomputed from the **current** coordinates at every increment (recommended for large‑deformation or when the reference node moves). |
| `USEREL=NO` (default) | The direction vector is taken from the **original** mesh coordinates (sufficient for small‑strain problems). |
| Data line | `reference‑node , slave‑node` – both are integer node IDs. |
| Multiple lines | You may list as many “reference, slave” pairs as you like under the same *MPC* block. |

---

## 2.  Minimal, working input‑file snippet  

```abaqus
*Heading
** Example: keep the distance between node 100 and node 200 constant
*Node
100, 0.0, 0.0, 0.0
200, 10.0, 0.0, 0.0
** (other nodes …)

*Element, type=C3D8
...                     (your element connectivity)

** -------------------------------------------------
**  Multi‑point constraint: distance = constant
** -------------------------------------------------
*MPC, TYPE=DISTANCE, USEREL=NO
100, 200                ! 100 = reference node, 200 = slave node
```

*If you want the direction to follow the deformed configuration, simply change the option:*

```abaqus
*MPC, TYPE=DISTANCE, USEREL=YES
100, 200
```

---

## 3.  Adding many distance constraints at once  

You do **not** need a separate *MPC* block for each pair.  List all pairs consecutively:

```abaqus
*MPC, TYPE=DISTANCE, USEREL=NO
100, 200
101, 205
102, 210
...   (as many as required)
```

Abaqus creates one independent constraint equation for every line.

---

## 4.  Things to watch out for  

| Potential problem | What to check / remedy |
|-------------------|------------------------|
| **Over‑constraining** | Ensure the two nodes are not already tied together by a *Tie*, *Rigid Body*, or another MPC. Duplicate constraints will make the system singular. |
| **Reference node belongs to a rigid body** | The distance constraint will also restrict the rigid body’s motion. Verify that this is intended. |
| **Large rotations / large‑deformation** | The original line direction may become inaccurate. Use `USEREL=YES` so the direction is updated each increment. |
| **Solver compatibility** | Distance MPCs are supported in static, quasi‑static, and dynamic analyses (implicit/explicit). They are treated as linear constraint equations, so they do not add non‑linearity beyond the usual material/geometry non‑linearity. |
| **Numbering** | Node IDs must be unique and correspond to nodes that actually exist in the model. A typo will cause the input file to abort. |
| **Performance** | Each distance MPC adds one equation to the global system. In very large models keep the number of distance constraints to the minimum required. |

---

## 5.  Quick checklist before you run

1. **Identify the node pair(s).**  
   Write down the reference‑node ID and the slave‑node ID for every distance you want to lock.  

2. **Choose the direction option.**  
   - `USEREL=NO` → use original mesh direction (default).  
   - `USEREL=YES` → recompute direction from the current deformed geometry (large rotations).  

3. **Insert the *MPC* block.**  
   Place the block **after** the *Node* and *Element* definitions and **before** the first *Step*.  

4. **List all pairs.**  
   One line per pair, e.g. `100, 200`.  

5. **Check for conflicts.**  
   Verify that none of the nodes are already constrained together by other features.  

6. **Run the analysis.**  
   Abaqus will automatically assemble the constraint equations and enforce a constant distance during the solution.  

---

### TL;DR

```abaqus
*MPC, TYPE=DISTANCE, USEREL=YES   ! or NO, depending on your problem
refNode1, slaveNode1
refNode2, slaveNode2
...
```

That’s everything you need to keep the Euclidean distance between any two (or many) nodes constant in an Abaqus model. Happy modelling!

Q: **Abaqus *inp* – distance‑type MPC (constant node‑to‑node distance)**

```text
*MPC, TYPE=DISTANCE, USEREL=YES|NO
reference‑node , slave‑node
```

|------|-----------|---------|

| `USEREL=YES` | optional | Re‑evaluate the line direction from the **current** coordinates at every increment (useful for large rotations or when the reference node moves). |
| `USEREL=NO` (default) | optional | Use the **original** mesh coordinates to define the line direction (sufficient for small‑strain problems). |
| Data line | **yes** | Two integer node IDs: **reference node**, **slave node**. |
| Multiple lines | optional | List as many “reference, slave” pairs as you need under the same *MPC* block. Abaqus creates one independent constraint equation per line. |

A: Below is a **ready‑to‑copy‑paste cheat‑sheet** for defining a **distance‑type multi‑point constraint (MPC)** in an Abaqus *.inp* file.  
Only the node numbers (and, optionally, the `USEREL` flag) need to be edited – everything else can be left exactly as shown.

---

## 1.  Keyword syntax  

```text
*MPC, TYPE=DISTANCE, USEREL=YES|NO
reference‑node , slave‑node
```

| Option | Required? | Meaning |
|--------|-----------|---------|
| `TYPE=DISTANCE` | **yes** | Enforces a **constant Euclidean distance** between the two nodes. |
| `USEREL=YES` | optional | Re‑evaluate the line direction **at every increment** from the **current** coordinates (needed when the reference node moves or for large rotations). |
| `USEREL=NO` (default) | optional | Use the **original mesh** coordinates to define the line direction (sufficient for small‑strain problems). |
| Data line | **yes** | Two integer node IDs: **reference node**, **slave node**. |
| Additional lines | optional | Add as many “reference, slave” pairs as you need – Abaqus creates one independent constraint equation per line. |

```abaqus
*Heading
** Example: keep the distance between node 100 and node 200 constant
*Node

** (other nodes …)

*Element, type=C3D8
...                     (your element connectivity)

** ---------- Distance‑type MPC ----------
*MPC, TYPE=DISTANCE, USEREL=NO
100, 200                ! 100 = reference node, 200 = slave node
```

*If the reference node is expected to move (or you have large rotations), use `USEREL=YES` instead:*

```abaqus
*MPC, TYPE=DISTANCE, USEREL=YES
100, 200
```

## 3.  Several constraints in one block  

```abaqus
*MPC, TYPE=DISTANCE, USEREL=NO
100, 200
101, 205
102, 210
...   ! add as many pairs as required
```

A **separate constraint equation** is generated for each line.

---

## 4.  Common pitfalls & how to avoid them  

| Pitfall | Why it occurs | Fix |
|---------|---------------|-----|
| **Over‑constraining (duplicate ties)** | Same node pair already linked by a *Tie*, *Rigid Body*, or another MPC. | List each pair only once and verify no other constraint already ties them together. |
| **Reference node moves but `USEREL=NO`** | Direction vector stays fixed, giving an unrealistic constraint after translation/rotation. | Use `USEREL=YES` when the reference node moves. |
| **Large rotations** | Fixed direction (`USEREL=NO`) may no longer be the correct line. | Set `USEREL=YES`. |
| **Rigid‑body interaction** | If the reference node belongs to a rigid body, the distance constraint also restricts that rigid body’s motion. | Confirm this is intended or pick a different reference node. |
| **Solver performance** | Each distance MPC adds one extra equation to the global system. | Keep the number of distance constraints to the minimum required. |

---

## 5.  Quick pre‑run checklist  

1. **Pick node pairs** – write down *reference‑node* and *slave‑node* IDs.  
2. **Select `USEREL`.**  
   * `NO` (default) → original mesh direction (good for small‑strain).  
   * `YES` → direction recomputed each increment (safer for moving/reference nodes or large rotations).  
3. **Insert the `*MPC` block** after the *Node*/*Element* sections and **before the first *Step***.  
4. **List all pairs** – one line per pair.  
5. **Check for conflicts** with other constraints (Tie, Rigid Body, other MPCs).  
6. **Run the analysis** – Abaqus will enforce a constant distance for every listed pair.

### 4. Common pitfalls & how to avoid them  

| Pitfall                              | Why it occurs                                            | Fix |
|--------------------------------------|----------------------------------------------------------|-----|
| **Over‑constraining (duplicate ties)** | Same node pair already tied by a *Tie*, *Rigid Body*, or another MPC. | List each pair only once and verify no other constraint already ties them together. |

| **Rigid‑body interaction**          | If the reference node belongs to a rigid body, the distance constraint also restricts that rigid body’s motion. | Confirm this is intended or pick a different reference node. |
