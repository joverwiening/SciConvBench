**Short answer** – The *deck‑printing* block that Abaqus stores in an *.odb* file is a **verbatim copy** of the input deck that was used for the analysis.  
Every character – commas, spaces, line‑breaks, comment lines (`** …`) and numeric values – is written to the ODB exactly as it appears in the *.inp* file. Nothing is added, removed or reformatted by the solver.

Consequently the block you see for **`case_116.inp`** inside `case_116.odb` is identical to the input deck you posted.

## How to view / extract the deck‑printing block yourself  

| Method | Steps |
|--------|-------|
| **Abaqus/CAE (GUI)** | 1. Open the ODB (`File → Open`).<br>2. In the **Visualization** module choose **Results → Output → Deck‑Printing** (or **View → Deck‑Printing** in newer versions).<br>3. The dialog shows the complete input deck exactly as it was written. |
| **Python script (odbAccess)** | ```python\nfrom odbAccess import openOdb\n\nodb = openOdb('case_116.odb')\n# whole deck is stored as a single string\ndeck = odb.deckPrinting   # or odb.rootAssembly.deckPrinting in older releases\nprint(deck)                # prints the unchanged input deck\nodb.close()\n```<br>Run the script with `abaqus python script.py`. |
| **Command‑line** | `abaqus odbreport -odb case_116.odb -report deckPrinting`<br>This prints the deck‑printing block to the console (redirect to a file if desired). |
