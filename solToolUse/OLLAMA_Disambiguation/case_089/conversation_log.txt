Q: **What Abaqus is trying to do**

When an amplitude is declared with the option **USER**

```abaqus
*AMPLITUDE,NAME=QUADRATIC,USER
```

Abaqus does **not** read the numbers that follow the keyword.  
Instead it calls the user subroutine **UAMP** (the name of the
subroutine is fixed – it must be called *UAMP*).  
The subroutine expects to read a **separate text file** that contains the
time‑amplitude pairs.  

If the name of that file is not given, Abaqus uses the amplitude name
(`QUADRATIC`) as the file name. Because there is no file called
*QUADRATIC* (or *QUADRATIC.txt*) in the working directory the solver stops
with the message

```
Error: the user amplitude file ... does not exist
```

So the problem is not the Fortran source file, it is the missing **amplitude
data file** (or the missing reference to it).

---

## How to fix it

### 1. Create a file that contains the amplitude data

The file can have any name, e.g. `quad.dat`. Its contents must be a list of
time‑value pairs, one pair per line, for example

```
0.0   0.0
0.5   0.25
1.0   1.0
```

(You can also leave the file empty – the subroutine can generate the
values itself – but the file must exist.)

### 2. Tell Abaqus which file to read

Add the file name on the line **immediately after** the *AMPLITUDE* keyword,
or use the optional `FILE=` parameter. Both ways are accepted.

**Option A – file name on the next line**

```abaqus
*AMPLITUDE,NAME=QUADRATIC,USER
quad.dat
```

**Option B – using the FILE= argument**

```abaqus
*AMPLITUDE,NAME=QUADRATIC,USER,FILE=quad.dat
```

### 3. Compile and link the user subroutine

The Fortran source that contains the routine `UAMP` must be compiled and
linked with the job. Do this with the `user=` option on the command line:

```bash
abaqus job=beam user=UAMP.f
```

(`UAMP.f` is the file that contains the subroutine you posted.)

Make sure that

* `UAMP.f` is in the same directory as the input file,
* the compiled object file (`UAMP.obj` or `UAMP.o`) is created,
* the job is started with the `user=` flag as shown above.

### 4. Full minimal example

```abaqus
*AMPLITUDE,NAME=QUADRATIC,USER,FILE=quad.dat
*STEP,NLGEOM
.5,1.
*END STEP
```

and the command line

```bash
abaqus job=beam user=UAMP.f
```

Now Abaqus will

1. read the file `quad.dat` (or the empty file) when it calls `UAMP`,
2. execute the code you wrote in `UAMP`,
3. continue with the analysis without the “user amplitude file does not exist”
   error.

---

### Summary of the required changes

| What you have | What you need to add / change |
|---------------|------------------------------|
| `*AMPLITUDE,NAME=QUADRATIC,USER` (no file name) | `*AMPLITUDE,NAME=QUADRATIC,USER,FILE=quad.dat` **or** add a line `quad.dat` after the keyword |
| No file called `quad.dat` (or `QUADRATIC`) in the working directory | Create that file (even if it is empty) |
| Job started without `user=` option | Run `abaqus job=… user=UAMP.f` |

After these modifications the user‑defined amplitude subroutine will be
found and the analysis will run.

## 4. Common pitfalls (and how to avoid them)

| Symptom | Typical cause | Fix |
|---------|---------------|-----|
| **“user amplitude file does not exist”** | • `*AMPLITUDE` line missing `USER` <br>• File name typo or file not in job directory <br>• File is binary or has Windows line‑ending problems on a Linux run | Verify the `*AMPLITUDE` line, check the exact file name, and make sure the file is plain ASCII. |
| **Linker error “UAMP not found”** | • Routine not compiled (`user=` omitted) <br>• Wrong file extension or case‑sensitivity on Linux | Use `abaqus … user=UAMP.f` (or `.c/.cpp/.for`). Ensure the source file name matches exactly. |
| **Segmentation fault / crash inside UAMP** | • Attempting to `OPEN`/`CLOSE` the file yourself <br>• Using the wrong data type for arguments (e.g., `REAL*4` instead of `DOUBLE PRECISION`) | Do **not** open/close the file; use the `FILEID` passed by Abaqus. Keep the argument list and types exactly as shown. |
| **Amplitude values are wrong or constant** | • Not advancing the file pointer correctly (reading the same line every call) <br>• Ignoring the `TIME` argument | Read a new line each call (as in the example) and compare `TIME` with the time read from the file before assigning `AMPL`. |
| **Job aborts after a few increments** | • `STATUS` never set to `1` → Abaqus thinks more data are available but reaches EOF and cannot read further | When `READ … END=EOF` is triggered, set `STATUS = 1` before returning. |

C -------------------------------------------------
C  USER‑DEFINED AMPLITUDE ROUTINE

## 4. Common pitfalls (and how to avoid them)

|---------|---------------|-----|
| “user amplitude file does not exist” | `*AMPLITUDE` line missing `USER`; typo in file name; file not in job directory; file is binary or has wrong line endings | Verify the `*AMPLITUDE` line, check the exact file name, and make sure the file is plain ASCII. |
| Linker error “UAMP not found” | Routine not compiled (`user=` omitted) or wrong file extension/case on Linux | Use `abaqus … user=UAMP.f` (or `.c/.cpp/.for`). Ensure the source file name matches exactly. |
| Segmentation fault inside `UAMP` | Trying to `OPEN`/`CLOSE` the file yourself; wrong data type for arguments | Use the `FILEID` passed by Abaqus; keep the argument list and types exactly as shown. |
| Wrong or constant amplitude values | Not advancing the file pointer (reading the same line each call) or ignoring `TIME` | Read a new line each call (as in the example) and compare `TIME` with the time read before assigning `AMPL`. |
| Job aborts after a few increments | `STATUS` never set to `1` → Abaqus thinks more data are available but reaches EOF | In the `END=EOF` branch set `STATUS = 1` before returning. |

## 4️⃣ Common pitfalls (and fixes)

| Symptom | Typical cause | Fix |
|---------|---------------|-----|
| “USER AMPLITUDE FILE DOES NOT EXIST” | `*AMPLITUDE` line missing `USER`; typo in file name; file not in job directory; file is binary or has Windows CR‑LF line endings on a Unix system | Verify the `*AMPLITUDE` line, check the exact file name, and make sure the file is plain ASCII (use a text editor, not Excel). |
| Linker error “UAMP not found” | Routine not compiled (`user=` omitted) or wrong file extension/case on Linux | Use `abaqus … user=UAMP.f` (or `.c/.cpp/.for`). Ensure the source file name matches exactly. |
| Segmentation fault inside `UAMP` | Trying to `OPEN`/`CLOSE` the file yourself; wrong data type for arguments | Use the `FILEID` passed by Abaqus; keep the argument list and types exactly as shown. |
| Constant or wrong amplitude values | Not advancing the file pointer (reading the same line each call) or ignoring `TIME` | Read a new line each call (as in the example) and compare `TIME` with the time read before assigning `AMPL`. |
| Job aborts after a few increments | `STATUS` never set to `1` → Abaqus thinks more data are available but reaches EOF | In the `END=EOF` branch set `STATUS = 1` before returning. |
