Q: What should be listed in the “artifacts” array of results.json (e.g., specific output files such as case_083.dat, case_083.frd, etc.)?
A: **Answer**

The `artifacts` array in `results.json` must contain **every file that is considered a final, user‑visible output of the run** – i.e., the files that someone reviewing the result would need to understand, verify, or reuse the work.  

In practice this means listing:

| Category | Typical file‑type / naming pattern | Why it belongs in `artifacts` |
|----------|-----------------------------------|--------------------------------|
| **Primary simulation results** | `case_083.dat`, `case_083.frd` (or whatever the case number is) | These are the core data files that contain the computed solution. |
| **Log / run‑summary files** | `case_083.log`, `case_083_summary.txt`, `run_info.json` | They record the execution details, convergence information, and any warnings/errors. |
| **Post‑processing / visualization files** | `case_083.png`, `case_083.pdf`, `case_083.vtk`, `case_083.csv` | Plots, meshes, or tables that are generated for reporting or further analysis. |
| **Metadata / provenance files** | `metadata.yaml`, `inputs_used.json`, `environment.txt` | Anything that documents the exact input set, software version, or environment used to produce the results. |
| **Auxiliary output required for downstream steps** | `case_083_boundary.dat`, `case_083_pressure.dat` | Files that are not the main solution but are needed by downstream tools or by the reviewer to fully interpret the results. |

### What **NOT** to include
- Temporary or intermediate files that are deleted or overwritten in later steps (e.g., `tmp_*.tmp`, checkpoint files that are not part of the final deliverable).
- Source code files, unless the repository explicitly requires them as part of the artifact bundle.
- Large raw input decks that are already stored elsewhere and referenced via a checksum or URL.

### How to format the array
```json
{
  "artifacts": [
    "case_083.dat",
    "case_083.frd",
    "case_083.log",
    "case_083_summary.txt",
    "case_083.png",
    "case_083.vtk",
    "metadata.yaml",
    "inputs_used.json"
  ]
}
```
- Use **relative paths** from the directory that contains `results.json`.
- Keep the list **alphabetically ordered** (or any deterministic order) to make diffs easier to read.
- If a file is inside a sub‑folder, include the folder name, e.g., `"plots/case_083_pressure.png"`.

### Bottom line
List **all final output files** that a consumer of the result would need—typically the main data files (`*.dat`, `*.frd`), any logs or summaries, visualisation artefacts, and provenance metadata. Anything that is merely a transient working file should be omitted.
