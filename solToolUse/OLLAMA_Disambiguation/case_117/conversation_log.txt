Q: **In short – use a *BOUNDARY (or *DISPLACEMENT) command, not an *EQUATION, for a simple prescribed displacement.**  

`*EQUATION` is the keyword for a **multi‑point constraint (MPC)** – i.e. a relation that ties the DOFs of two or more nodes together.  
If you only want to prescribe a displacement (or a set of displacements) on a node or a node set, the proper Abaqus syntax is the *BOUNDARY option (or the *DISPLACEMENT sub‑option inside a *STEP).

---

## 1. What the *EQUATION you wrote actually does  

```
*EQUATION
2
105,3,1.,129,3,-1.
```

* The first line (`2`) tells Abaqus that the equation has **two terms**.  
* The second line gives the two terms:  

  - Node 105, DOF 3, coefficient +1.0  
  - Node 129, DOF 3, coefficient ‑1.0  

The resulting constraint is  

\[
1\;U_{3}(105) \;-\; 1\;U_{3}(129) \;=\;0
\]

i.e. **U₃(105) = U₃(129)**.  
That is a *tie* (or “equal‑displacement”) condition between the two nodes, **not** a prescribed displacement.

If you really need that tie, the syntax is correct (the two terms may be written on separate lines, but a single line works as well).  

---

## 2. How to prescribe a displacement

### a) Using *BOUNDARY (the most common way)

```abaqus
*BOUNDARY, NSET=FIX
1, 1, 3, 0.0          ; fix node 1 in DOFs 1‑3 (U1=U2=U3=0)
...
105, 3, 3, 0.005      ; prescribe U3 = 0.005 at node 105
```

* **NSET** – the set of nodes on which the condition is applied.  
* **DOF‑start, DOF‑end** – the degree(s) of freedom (1 = X‑translation, 2 = Y‑translation, 3 = Z‑translation, 4‑6 = rotations for 3‑D).  
* **Value** – the magnitude of the prescribed displacement (positive or negative).  

You can also apply the same value to a whole node set in one line:

```abaqus
*BOUNDARY, NSET=N1, DOF=3, VALUE=0.0
```

### b) Using *DISPLACEMENT inside a *STEP (alternative syntax)

```abaqus
*STEP
*BOUNDARY
N1, 3, 3, 0.0          ; same as above, but placed inside the step
*END STEP
```

Both *BOUNDARY and *DISPLACEMENT are interpreted by Abaqus as **prescribed displacement** boundary conditions.

---

## 3. When to use *EQUATION (MPC) instead

Use *EQUATION only when you need a **relationship** between two (or more) DOFs, e.g.:

* Tying two nodes together (U₁ = U₂).  
* Enforcing a linear combination of DOFs (e.g., U₁ + 2 U₂ = 5).  
* Implementing a rigid body constraint that is not a simple “fixed” condition.

If you only want to **set** a displacement value, *BOUNDARY is the correct and simpler choice.

---

## 4. Quick checklist – “Did I prescribe the BC correctly?”

| What you want to do | Keyword to use | Typical line format |
|---------------------|----------------|---------------------|
| Fix a node (all 6 DOFs) | `*BOUNDARY` | `node, 1, 6, 0.0` |
| Prescribe a single DOF (e.g., U₃ = 0.005) | `*BOUNDARY` | `node, 3, 3, 0.005` |
| Tie two nodes together (U₃(105)=U₃(129)) | `*EQUATION` | `2`<br>`105,3,1.,129,3,-1.` |
| Apply a rotation or a combination of DOFs | `*EQUATION` | as above, with the appropriate coefficients |
| Apply a distributed load (pressure, body force) | `*DLOAD`, `*CLOAD`, `*CFLUX` | … |
| Apply a point load (force) | `*CLOAD` | `node, DOF, magnitude` |

## 5. Example – fixing the left face and prescribing a vertical displacement at node 105

```abaqus
*NSET, NSET=FIX, GENERATE
1, 97, 1          ; all nodes on the left face (example)

*BOUNDARY, NSET=FIX
1, 1, 6, 0.0      ; fix all 6 DOFs on the left face

*BOUNDARY, NSET=N1
105, 3, 3, 0.005  ; prescribe U3 = +5 mm at node 105
```

If you also need node 129 to move the same amount (i.e., the two nodes must stay together), you would add an *EQUATION:

```abaqus
*EQUATION
2
105, 3, 1.0,
129, 3, -1.0
```

but **do not** combine this with a *BOUNDARY on the same DOF – that would over‑constrain the model.

- **Prescribed displacement → `*BOUNDARY` (or `*DISPLACEMENT` inside a step).**  
- **Tie / linear relation between DOFs → `*EQUATION` (MPC).**

## 1. How to prescribe a displacement correctly

### a) Using `*BOUNDARY` (the most common form)

```abaqus
*BOUNDARY, NSET=DISP_NODES
105, 3, 3, 0.005      ; U3 = +5 mm at node 105
```

- **NSET** – name of a node set that contains the node(s) you want to control.  
- **first‑DOF, last‑DOF** – the degree(s) of freedom to which the value applies (1‑X, 2‑Y, 3‑Z, 4‑RX, 5‑RY, 6‑RZ).  
- **value** – the prescribed displacement (positive or negative).  

You can also write the same line without a node set:

```abaqus
*BOUNDARY
105, 3, 3, 0.005
```

### b) Using `*DISPLACEMENT` inside a step (alternative syntax)

```abaqus
*STEP, NAME=STEP-1, NLGEOM=YES
*BOUNDARY
105, 3, 3, 0.005
*END STEP
```

`*DISPLACEMENT` is just a synonym for `*BOUNDARY` when it appears inside a step; the effect is identical.

### c) Fixing a whole face (or a group of nodes)

```abaqus
*NSET, NSET=LEFT_FACE, GENERATE
1, 97, 1               ; example – nodes 1‑97 belong to the left face

*BOUNDARY, NSET=LEFT_FACE
1, 1, 6, 0.0           ; fix all 6 DOFs on that face
```

## 2. When you *do* need `*EQUATION`

| Situation | Why `*EQUATION` is required |
|-----------|-----------------------------|
| **Tie two nodes together** (U3(105)=U3(129)) | You want the two DOFs to stay equal, but you do **not** prescribe a numeric value. |
| **Linear combination of DOFs** (U1 + 2 U2 = 5) | The constraint involves more than one DOF and a constant term. |
| **Rigid‑body constraint that is not a simple “fixed” condition** | You need a relationship such as “the rotation of node A equals twice the translation of node B”. |

The general form is  

```
*EQUATION
nterms
node1, dof1, coeff1, node2, dof2, coeff2, … , nodeN, dofN, coeffN, [constant]
```

* `nterms` = number of node‑DOF pairs (the “terms”).  
* The optional **constant** appears after the last coefficient and represents the right‑hand side of the equation.

**Example – tie two nodes in the Z‑direction**

```abaqus
*EQUATION
2
105, 3, 1.0,
129, 3, -1.0
```

This is exactly the same as the line you wrote; it is correct **only** if the intention is to keep the two nodes together.

---

## 3. Common pitfalls & how to verify

| Pitfall | Symptom | Fix |
|---------|---------|-----|
| Mixing `*BOUNDARY` and `*EQUATION` on the same DOF of the same node | Model over‑constrained → “singular matrix” or “over‑constrained” error. | Use **either** a prescribed value **or** an equation, never both on the same DOF. |
| Forgetting the `NSET` argument when you intend to apply the BC to many nodes | Only the first node gets the BC, others remain free. | Either list each node explicitly or create a node set (`*NSET`) and reference it. |
| Using the wrong DOF number (e.g., 3 for Z‑translation in a 2‑D model) | BC is ignored because that DOF does not exist. | Check the model dimensionality: 2‑D has DOFs 1‑2 (translations) and optionally 3 (out‑of‑plane rotation). |
| Supplying a negative value when you meant a positive displacement (or vice‑versa) | Unexpected deformation direction. | Verify sign conventions: positive X = +X direction, positive Y = +Y, positive Z = +Z. |
| Not placing the `*BOUNDARY` line inside the correct step | BC applied in the wrong load step or not at all. | Put the `*BOUNDARY` (or `*DISPLACEMENT`) line **inside** the step where the condition should be active, or use the global `*BOUNDARY` (outside any step) for a time‑independent condition. |

You can check that the BC has been read correctly by:

1. Opening the **Input File** (`.inp`) after you generate it from the GUI – the `*BOUNDARY` lines should be present exactly as you wrote them.  
2. Running a **quick analysis** with `*STEP, NLGEOM=NO` and looking at the **Message** file (`.msg`). Abaqus prints a summary of the applied boundary conditions.  
3. In the **Visualization** module, after the first increment, use **Tools → Query → Node** to read the displacement of the constrained node – it should match the prescribed value (or be zero if it is fixed).

### 1. Prescribing a displacement correctly  

#### a) Using `*BOUNDARY` (most common)

```abaqus
*BOUNDARY, NSET=DISP_NODES
105, 3, 3, 0.005      ; U3 = +5 mm at node 105
```

* **NSET** – name of a node set that contains the node(s) you want to control (you can also omit the set and list the node number directly).  
* **first‑DOF, last‑DOF** – the degree(s) of freedom to which the value applies (1‑X, 2‑Y, 3‑Z, 4‑RX, 5‑RY, 6‑RZ).  
* **value** – prescribed displacement (positive or negative).

The same line without a node set:

```abaqus
*BOUNDARY
105, 3, 3, 0.005
```

#### b) Using `*DISPLACEMENT` inside a step (alternative syntax)

```abaqus
*STEP, NAME=STEP-1, NLGEOM=YES
*Static
*DISPLACEMENT
105, 3, 3, 0.005
*END STEP
```

`*DISPLACEMENT` is just a synonym for `*BOUNDARY` when it appears inside a step; the effect is identical.

```abaqus
*NSET, NSET=FIXED, GENERATE
1, 97, 1               ; example – nodes 1‑97 belong to the left face
*END NSET

*BOUNDARY, NSET=FIXED
```

### 2. When you *do* need `*EQUATION`

| Situation | Why `*EQUATION` is required |
|-----------|-----------------------------|
| Tie two nodes together (e.g., U₃(105)=U₃(129)) | You want the two DOFs to stay equal, but you are **not** prescribing a numeric value. |
| Linear combination of DOFs (e.g., U₁ + 2 U₂ = 5) | The constraint involves more than one DOF and a constant term. |
| Complex rigid‑body relationship that cannot be expressed with a simple `*BOUNDARY` | A relationship that needs coefficients and possibly a constant term. |

**General syntax**

```
*EQUATION
nterms
node1, dof1, coeff1, node2, dof2, coeff2, … , nodeN, dofN, coeffN, [constant]
```

* `nterms` – number of node‑DOF pairs (the “terms”).  
* The optional **constant** appears after the last coefficient and represents the right‑hand side of the equation.

**Example – tie two nodes in Z**

```abaqus
*EQUATION
2
105, 3,  1.0,
129, 3, -1.0
```

This is exactly the line you wrote; it is correct **only** if the intention is to keep the two nodes together.

### 3. Common pitfalls & how to verify

| Pitfall | Symptom | Fix |
|---------|---------|-----|
| Mixing `*BOUNDARY` and `*EQUATION` on the same DOF of the same node | Model over‑constrained → “singular matrix” or “over‑constrained” error. | Use **either** a prescribed value **or** an equation, never both on the same DOF. |
| Forgetting the `NSET` argument when you intend to apply the BC to many nodes | Only the first node gets the BC, others remain free. | Either list each node explicitly or create a node set (`*NSET`) and reference it. |
| Using the wrong DOF number (e.g., 3 for Z‑translation in a 2‑D model) | BC is ignored because that DOF does not exist. | Check model dimensionality: 2‑D has DOFs 1‑2 (translations) and optionally 3 (out‑of‑plane rotation). |
| Supplying a negative value when you meant a positive displacement (or vice‑versa) | Unexpected deformation direction. | Verify sign conventions: positive X = +X direction, positive Y = +Y, positive Z = +Z. |
| Not placing the `*BOUNDARY` line inside the correct step | BC applied in the wrong load step or not at all. | Put the `*BOUNDARY` (or `*DISPLACEMENT`) line **inside** the step where the condition should be active, or use the global `*BOUNDARY` (outside any step) for a time‑independent condition. |

#### How to check that the BC has been read correctly  

1. Open the generated **.inp** file – the `*BOUNDARY` lines should appear exactly as you wrote them.  
2. Run a quick analysis and look at the **Message** file (`.msg`); Abaqus prints a summary of the applied boundary conditions.  
3. After the first increment, use **Tools → Query → Node** in the Visualization module; the displacement of the constrained node should match the prescribed value (or be zero if it is fixed).

| Tie two or more DOFs together, or impose a linear relation | `*EQUATION` (multi‑point constraint) | Outside the `*STEP` blocks – it defines a relationship, **not** a prescribed value |
| **Never** combine `*BOUNDARY`/`*DISPLACEMENT` with an `*EQUATION` on the same DOF – it over‑constrains the model and leads to a singular‑matrix error. |

Below is a step‑by‑step guide that shows how to apply a displacement correctly and why `*EQUATION` is not the right tool for this job.

---------------------------------------------------------------------

## 1.  Prescribing a displacement – the **right** way  

### a) Global (permanent) boundary condition  

Place the `*BOUNDARY` line **outside** any `*STEP`.  
The condition will be active for **all** steps of the analysis.

```abaqus
*BOUNDARY, NSET=DISP_NODES          ; recommended: use a node set
105, 3, 3, 0.005                    ; node 105, DOF 3 (Z), +5 mm
```

or, without a node set:

```abaqus
*BOUNDARY
105, 3, 3, 0.005
```

| Column | Meaning |
|--------|---------|
| node (or node‑set name) | the node that receives the BC |
| first‑DOF | 1‑X, 2‑Y, 3‑Z, 4‑RX, 5‑RY, 6‑RZ |
| last‑DOF | same as first if only one DOF |
| value | prescribed displacement (positive = + direction of the axis) |

### b) Step‑specific displacement  

If the displacement should be applied **only** during a particular step, put it inside that step. Inside a step the keyword is called `*DISPLACEMENT`; it is just a synonym for `*BOUNDARY`.

```abaqus
*STEP, NAME=STEP-1, NLGEOM=YES
*STATIC
*DISPLACEMENT
105, 3, 3, 0.005
*END STEP
```

Both the global `*BOUNDARY` and the step‑specific `*DISPLACEMENT` give the same numerical result; the only difference is the **time span** of the condition (permanent vs. step‑limited).

---------------------------------------------------------------------

## 2.  When you really need `*EQUATION`

`*EQUATION` **does not** prescribe a displacement. It creates a **linear relationship** (a multi‑point constraint, MPC) among several degrees of freedom. Use it only when you need to:

* **Tie two (or more) nodes together** – e.g. enforce `U3(105) = U3(129)`.
* **Impose a linear combination** of DOFs – e.g. `U1 + 2·U2 = constant`.

### Example – tie two nodes in the Z‑direction

```abaqus
*EQUATION
2                     ; number of terms in the equation
105, 3,  1.0,         ; +1·U3(105)
129, 3, -1.0          ; -1·U3(129)  →  U3(105) – U3(129) = 0
```

### Example – tie them **and** prescribe a 5 mm offset

```abaqus
*EQUATION
2
105, 3,  1.0,
129, 3, -1.0, 0.005   ; U3(105) – U3(129) = 0.005
```

> **Important:** Never apply a `*BOUNDARY` (or `*DISPLACEMENT`) to any DOF that already appears in an `*EQUATION`. Doing so over‑constrains the model and typically produces a “singular matrix” error.

---------------------------------------------------------------------

## 3.  How to fix the situation you described  

You tried to prescribe a displacement with `*EQUATION`, which is the wrong keyword for that purpose. Follow these steps:

1. **Delete** the `*EQUATION` block that involves node 105 (unless you truly need a multi‑point constraint).  
2. **Add** a proper displacement prescription:

   *Permanent (global) BC*

   ```abaqus
   *BOUNDARY
   105, 3, 3, 0.005   ; +5 mm in Z at node 105 for the whole analysis
   ```

   *or, if the displacement should act only during a particular step*

   ```abaqus
   *STEP, NAME=STEP-1, NLGEOM=YES
   *STATIC
   *DISPLACEMENT
   105, 3, 3, 0.005
   *END STEP
   ```

3. Run the analysis. The model now has **one** correctly‑prescribed displacement on node 105 and **no conflicting constraints**, so the solver will not encounter a singular‑matrix problem.
