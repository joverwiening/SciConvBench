Create the file beamp.inp with the exact content provided in the Global model input deck section.
Run the global model with the command: ccx -i beamp
Check beamp.sta for successful completion of the global run.
Copy beamp.frd to beamp.frd.ref using: cp beamp.frd beamp.frd.ref
Create the file case_134.inp with the exact content provided in the Submodel input deck section.
Run the submodel with the command: ccx -i case_134
Check case_134.sta for a line containing JOB COMPLETED to determine success or failure.
Obtain the CalculiX version string by running: ccx -v
Write a results.json file in the working directory with the following fields: solver set to calculix, case_id set to case_134, status set to success if case_134.sta contains JOB COMPLETED and error otherwise, ccx_version set to the version string obtained from ccx -v, artifacts set to a list of output files produced (e.g. case_134.frd, case_134.dat, case_134.sta), and notes set to the exact commands used in order: ccx -i beamp, cp beamp.frd beamp.frd.ref, ccx -i case_134, plus any failure messages encountered.
The submodel input references beamp.frd.ref via the line INPUT=beamp.frd.ref inside the SUBMODEL keyword, so the copy must be named exactly beamp.frd.ref and must reside in the same working directory as both input files.
Do not modify any physics, boundary conditions, material definitions, element definitions, or step definitions in either input deck.
The global model beamp.inp uses a SECTION PRINT step with no material properties defined under MATERIAL NAME=EL and no ELASTIC card; this is intentional and must be preserved exactly as given.
The submodel case_134.inp uses BOUNDARY,SUBMODEL,STEP=1 applied to node set Nall with DOFs 1 through 3, driven by the global results in beamp.frd.ref; this must be preserved exactly as given.
If beamp.frd is not produced after the global run, search the working directory for any .frd file produced by the ccx -i beamp run and copy that file to beamp.frd.ref, recording the actual filename found in the notes field of results.json.
If the submodel run fails, set status to error in results.json and record the failure message from case_134.sta or standard output in the notes field.
