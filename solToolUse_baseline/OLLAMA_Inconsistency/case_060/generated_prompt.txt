**Short answer**

```bash
# Generic call – uses the first `ccx` found in $PATH
ccx  axiplane          # reads axiplane.inp (do NOT add .inp)

# If you need a particular version (e.g. CalculiX 2.19)
ccx_2.19  axiplane
```

`axiplane` is the **base name** of the input file `axiplane.inp`.  
Call the **real `ccx` executable** (or a version‑specific binary such as `ccx_2.19`) directly; do **not** use the `calculix` wrapper script.  

**Why call `ccx` directly?**

| Reason | Benefit of `ccx` (or `ccx_<ver>`) | What you lose with the `calculix` wrapper |
|--------|-----------------------------------|-------------------------------------------|
| Exact version control | Choose a specific binary (`ccx_2.19`, `ccx_2.20`, …) → reproducible runs | Wrapper may silently pick the first `ccx` it finds |
| Unfiltered output | All warnings/errors appear unchanged; exit status (`$?`) reflects the real solver result | Wrapper can add its own messages, filter output, or mask the true exit code |
| Portability | Any proper CalculiX installation provides a `ccx` binary in `$PATH`; scripts work on Linux, macOS, Windows (WSL/Cygwin) | Wrapper is just a convenience script that may be missing or behave differently on other platforms |
| Simplicity & speed | No extra shell indirection → marginally faster start‑up | Wrapper adds an extra process and extra checks |

**How to run it correctly**

1. Ensure the binary is in your `PATH` (`which ccx`).
2. Pick the binary you want (`ccx` for the default, `ccx_2.19` for a specific version).
3. Invoke it with the **base name** of the input file (do **not** add `.inp`; `ccx` appends it internally).

```bash
# Input file is axiplane.inp
ccx  axiplane          # reads axiplane.inp automatically
# or, force a specific version
ccx_2.19  axiplane
```

4. (Optional) Check the exit status in scripts:

```bash
ccx axiplane
rc=$?
if (( rc != 0 )); then
    echo "ERROR: CalculiX failed (exit code $rc)" >&2
    exit $rc
fi
```

Calling `ccx` directly gives you exact version selection, clean unfiltered output, reliable exit codes, and maximum portability—ideal for both interactive use and automated pipelines. Happy solving!
