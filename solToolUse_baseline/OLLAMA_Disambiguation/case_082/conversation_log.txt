Q: Should the artifacts array list just the filenames (e.g., case_082.sta, case_082.log) or include relative paths to those files?
A: **Answer:**  
The `artifacts` array must contain **relative paths** to the files, not just the bare filenames.

**Why the full requirement says this**

- The specification defines each entry in `artifacts` as “a path, relative to the root of the artifact bundle, that points to a file that should be uploaded/archived.”  
- Using only the filename would be ambiguous when multiple files with the same name exist in different sub‑folders (e.g., `logs/case_082.log` vs. `output/case_082.log`).  
- Consumers of the artifact list (CI runners, downstream jobs, or reporting tools) resolve the entries by joining the provided string with the artifact root directory. If only a filename is supplied, the resolver cannot know which sub‑directory to look in, leading to “file not found” errors.

**What to put in the array**

```json
{
  "artifacts": [
    "output/case_082.sta",
    "logs/case_082.log"
  ]
}
```

If the files are located directly at the root of the artifact bundle, the relative path is simply the filename (e.g., `"case_082.sta"`). But whenever a file lives inside a sub‑directory, the path must include that directory component. This satisfies the complete requirement and ensures reliable artifact handling.
