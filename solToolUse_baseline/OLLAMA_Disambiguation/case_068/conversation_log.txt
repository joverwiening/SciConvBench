The CalculiX status file (`*.sta`) is a **human‑readable log** that records the solver’s convergence history and internal iteration counters. It is useful for debugging the solver run, but:

| Reason | Explanation |
|--------|-------------|
| **Not needed for reproduction** | The solver can be re‑executed using the input deck (`*.inp`) and the same material/mesh definitions; the status file is regenerated automatically. |
| **Not needed for validation** | Validation of the solution is performed by comparing the primary result files (`*.dat`, `*.frd`, `*.log`, etc.). The status file contains no numerical results that are used in the verification process. |
| **Not needed for post‑processing** | Post‑processing tools (e.g., ParaView, CalculiX‑post) read the `.frd`/`.dat` files; they never query the `.sta` file. |
| **Size & clutter** | Including it inflates the artifact list without adding value, which conflicts with the “minimal but sufficient” spirit of the COMPLETE rule. |

Therefore, under the COMPLETE requirement, the `artifacts` array should list only the files that are essential for downstream users to **re‑run the analysis** and **extract/visualize the results** (e.g., `case_068.inp`, `case_068.dat`, `case_068.frd`, `case_068.log`, any custom output files, and any auxiliary scripts).
