## ✅ 3️⃣ TROUBLESHOOTING (if any row is red)

| Symptom | Typical cause | One‑line fix to try |
|---------|---------------|---------------------|
| Divergence on the first increment | Load step too aggressive. | Reduce the initial increment, e.g. change `*STATIC, INC=0.02` → `*STATIC, INC=0.005`. |
| “Maximum number of iterations exceeded” | Plasticity changes stiffness rapidly. | Add inside the step: `*CONTROLS, PARAMETERS=MAXIMUM, INCREMENT=200`. |
| No convergence after many increments | Mesh too coarse or element distortion. | Refine the mesh (e.g. 10 × 10 × 10) or add a finer mesh near the loaded faces. |
| Reaction forces don’t match loads | Over‑/under‑constrained BCs or wrong load sign. | Verify exactly six independent DOFs are fixed (three corner nodes) and that the `*CLOAD` values have the correct sign. |
| “Node set not found” | Typo in node‑set name. | Ensure the names in `*CLOAD, NSET=` match the `*NSET` definitions **exactly** (case‑sensitive). |
| Units mismatch (wild deformation) | One coordinate entered in meters or a load in kN. | Re‑check that all lengths are **mm**, material stiffness **MPa**, loads **N**. |
| Very distorted elements in ODB | Large plastic strain + coarse mesh. | Refine the mesh locally or use reduced‑integration elements (`C3D8R`). |

> **After any change, delete the old result files** (`.odb`, `.dat`, `.msg`, `.sta`) before re‑submitting.
