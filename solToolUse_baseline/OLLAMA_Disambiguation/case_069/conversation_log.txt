## 2️⃣  Common pitfalls for **node‑to‑surface penalty** contacts

### 2.1  What “node‑to‑surface” really means

| Side | Definition |
|------|------------|
| **Slave** | A **node set** (the nodes that may penetrate the master). In the input file you must give a *NSET* that contains **only the slave nodes**. |
| **Master** | A **surface** (a collection of element faces). The master surface can be any *S*‑type surface (S3, S4, S5, …). |

> **Your current file** defines `Sslav` as a *surface* (`*SURFACE, NAME=Sslav`). That is **incorrect** for a *node‑to‑surface* pair – Abaqus expects a **node set** as the first argument. The job will abort with an error such as  
> `ERROR: Invalid contact pair definition – slave must be a node set`.

### 2.2  Minimal fix – turn the slave surface into a node set

1. **Create a node set that contains all nodes of the slave block** (the “bottom” block that will be pressed against the top block).  
   The easiest way is to reuse the existing `Nload` set (the nodes that you actually load) **or** create a new set that contains *all* nodes of the slave block.  
   For a quick test you can use the nodes that belong to the slave surface (elements 28‑52). The node numbers are already listed in the *NODE* section, so you can pick a convenient range, e.g.:

   ```text
   *NSET, NSET=Nslav
   65,66,67,68,69,70,71,72,
   73,74,75,76,77,78,79,80,
   81,82,83,84,85,86,87,88,
   89,90,91,92,93,94,95,96,
   97,98,99,100,101,102,103,104,
   105,106,107,108,109,110,111,112,
   113,114,115,116,117,118,119,120,
   121,122,123,124,125,126,127,128
   ```

   (That set simply contains **all nodes of the slave block** – you can trim it later.)

2. **Replace the contact‑pair line** with the node set name as the first entry:

   ```text
   *CONTACT PAIR, INTERACTION=SI1, TYPE=NODE TO SURFACE
   Nslav, Smast
   ```

   *`Sslav` is no longer needed as a surface; you can delete the `*SURFACE, NAME=Sslav` definition (or keep it if you want a surface‑to‑surface version later).*

### 2.3  Penalty stiffness (the “over‑closure” parameter)

You already have:

```text
*SURFACE BEHAVIOR, PRESSURE-OVERCLOSURE=LINEAR
1.e6, 3.
```

* `1.e6` = penalty stiffness (N/m³).  
* `3.` = exponent that controls how the stiffness grows with the amount of over‑closure (the default is 1.0).

**Rule of thumb:**  
`penalty ≈ 10 × (E / h)` where `E` is a characteristic Young’s modulus of the contacting bodies and `h` is a typical element size on the master surface.  
Because you have **no material definition yet**, you cannot compute a sensible value. Use a **very soft** penalty for the first run (e.g. `1e5` N/m³) and increase it only if the contact “sticks” (i.e. you see large gaps or unrealistic interpenetration).

### 2.4  Mesh compatibility & clearance

| Issue | What to check |
|-------|---------------|
| **Slave nodes must lie on the slave surface** | Visualise the slave node set (`Nslav`) and the master surface (`Smast`) in CAE → *Interaction → Contact* → *Edit* → *View* → *Contact Diagnostics*. |
| **No initial gap** | The slave nodes should be **just touching** or **slightly penetrating** the master surface. If the slave block is initially separated by more than a few percent of the element size, the penalty algorithm may never engage. |
| **Element type** | You are using `C3D8` (linear brick) – fine for a static contact. Ensure that the slave side does **not** contain *zero‑thickness* elements (you don’t). |
| **Element‑face orientation** | The master surface you selected (`S5`) must be the **outer** face of the master block (the one that will be contacted). In your model `S5` belongs to elements 3, 6, 9, 12, 15, 18, 21, 24, 27 – those are the **top** faces of the upper block, which is correct. |

**Quick pre‑run check** (no solver needed):

```text
*STEP, NLGEOM
*STATIC
*CONTACT DIAGNOSTICS
```

Add the above *CONTACT DIAGNOSTICS* line (or use the CAE “Contact Diagnostics” tool) – it will write a short report in the `.dat` file telling you whether any slave node is initially **outside** the master surface, whether the clearance is negative, etc.

## 3️⃣  Interpreting the contact output

### 3.1  What you asked Abaqus to write

```text
*CONTACT FILE
CDISP, CSTRESS
```

* `CDISP` – **contact displacement** (relative normal approach of each slave node).  
* `CSTRESS` – **contact pressure** (the normal pressure that the penalty algorithm computes).  

Both are written to the **`.fil`** file (binary) and can be extracted with the **Visualization module** or with the **`abaqus viewer`** command.

### 3.2  Quick visual checks in Abaqus/CAE

1. **Open the ODB** (`case.odb`).  
2. In the **Viewport**, go to *Result → Field Output → Contact* → choose **`CPRESS`** (contact pressure) and **`CSTATUS`** (contact status).  
   * `CSTATUS = 1` → active contact (nodes are in contact).  
   * `CSTATUS = 0` → no contact (gap > 0).  
3. Plot **`U`** (displacements) on the deformed shape.  
   * The loaded nodes (your `Nload` set) should move **downward** (negative Z) by roughly the amount that would close the gap between the two blocks.  
   * The fixed nodes (`Nfix`) should stay at zero displacement.  

**Typical “good” pattern** for this simple block‑on‑block test:

| Quantity | Expected pattern |
|----------|------------------|
| **Contact pressure** | Zero everywhere **except** on the region where the slave block actually touches the master (the overlapping area). The pressure should be roughly `P = 100 N / area_of_loaded_face`. |
| **Contact status** | 1 (active) on the same region, 0 elsewhere. |
| **Displacements** | The slave block should translate downward until the loaded face is flush with the master face; the rest of the model should show a smooth, linear‑elastic deformation. |

### 3.3  Extracting numbers (optional)

If you prefer a quick numeric check without opening CAE, you can read the contact pressure from the **`.dat`** file (it contains a table called **`CONTACT PRESSURE`** when you request `*CONTACT FILE`). Example snippet:

```
   CONTACT PRESSURE
   NODE   CPRESS
   123    1.23E+04
   ...
```

Or use the **`abaqus python`** script:

```python
from odbAccess import *
odb = openOdb('case.odb')
step = odb.steps['Step-1']
frame = step.frames[-1]               # last increment
cpress = frame.fieldOutputs['CPRESS']
# write to a text file
with open('contact_pressure.txt','w') as f:
    for v in cpress.values:
        f.write(f'{v.nodeLabel:8d} {v.data[0]:12.5e}\n')
odb.close()
```

That will give you a list of node‑wise pressures that you can plot in Excel, MATLAB, etc.

## 🔍 Quick sanity‑check that the contact is active  

| What to look at | Where to find it | Expected result |
|-----------------|------------------|-----------------|
| **Contact pressure** (`CPRESS`) | `case.odb` → *Result → Field Output → Contact → CPRESS* | Zero everywhere **except** on the overlapped area; magnitude ≈ *applied load / contact‑area*. |
| **Contact status** (`CSTATUS`) | Same menu, select `CSTATUS` | Value `1` (active) on the same region, `0` elsewhere. |
| **Displacements** (`U`) | Plot `U` on the deformed shape | Nodes in the loaded set move down until they touch the master surface; fixed nodes stay at zero. |
| **Diagnostics** (if you kept `*CONTACT DIAGNOSTICS`) | Open `case.dat` and search for “CONTACT DIAGNOSTICS” | A short table reporting any initial gaps. No large positive gaps → contact will engage. |

## 📂 (Optional) Extract contact pressure to a text file

```python
# extract_cpress.py
from odbAccess import openOdb
odb = openOdb('case.odb')
step = odb.steps['Step-1']
frame = step.frames[-1]               # last increment
cpress = frame.fieldOutputs['CPRESS']
with open('contact_pressure.txt','w') as f:
    for v in cpress.values:
        f.write(f'{v.nodeLabel:8d} {v.data[0]:12.5e}\n')
odb.close()
```

Run it:

```bash
abaqus python extract_cpress.py
```

`contact_pressure.txt` can be plotted in Excel, MATLAB, Python, etc.
