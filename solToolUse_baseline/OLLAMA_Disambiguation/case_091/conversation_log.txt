Q: Which files, if any, should be listed in the `artifacts` array of the `results.json` output?
A: **Answer**

Only **real output files that the agent creates for the caller** belong in the `artifacts` array of `results.json`.  
If the agent does not generate any such files, the array should be empty (or omitted entirely).

| When to include a file | What to put in `artifacts` |
|------------------------|----------------------------|
| The agent writes a file that the caller is expected to download, view, or further process (e.g., a PDF report, a PNG chart, a CSV data dump, a compiled binary, etc.). | The **relative path** (from the root of the agent’s working directory) to that file. |
| The file is only a temporary helper (e.g., a lock file, a cache, an intermediate log that the caller never needs). | **Do not** list it. |
| No files are produced at all (the result is purely JSON data). | `artifacts: []` (or omit the key). |

### Concrete examples

```json
{
  "status": "success",
  "output": { "summary": "Analysis complete." },
  "artifacts": [
    "reports/analysis.pdf",
    "charts/accuracy.png",
    "data/results.csv"
  ]
}
```

```json
{
  "status": "success",
  "output": { "message": "All done, nothing to download." },
  "artifacts": []          // <-- no files to return
}
```

### Summary (the “COMPLETE” requirement)

- **List** every file that the agent intends the caller to receive.
- **Use** the file’s path **relative to the agent’s root directory**.
- **Exclude** any internal‑only or temporary files.
- **If none exist**, provide an empty array (or omit the field).

### Why?

The **COMPLETE** requirement for a `results.json` file (as defined in the specification you’re following) states that **every file produced by the run that is intended to be retained, inspected, or consumed downstream must be enumerated in the `artifacts` array**. The purpose of this rule is to guarantee that:

1. **All output files are discoverable** – downstream tools, reviewers, or automated pipelines can locate every result without having to guess filenames or scan the directory.
2. **Reproducibility is ensured** – the manifest (`results.json`) fully describes the run’s output, making it possible to reconstruct the exact set of files later.
3. **Integrity checks can be performed** – many pipelines compute checksums for each listed artifact; if a file is omitted, its integrity cannot be verified.
