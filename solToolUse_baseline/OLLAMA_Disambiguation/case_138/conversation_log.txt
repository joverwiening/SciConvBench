Q: **What the error means**

In Abaqus a *COUPLING (kinematic) constraint creates a set of equations that relate the
displacements (or rotations) of the *reference node* to the average displacement of
all the nodes that belong to the *surface* you specify.  
If a degree of freedom (DOF) that is being coupled is already constrained by some
other equation or a boundary condition, the system of equations becomes **over‑
constrained** – Abaqus therefore stops with the message

```
*** ERROR: The constraint equation is over defined
```

In practice this most often happens when the reference node itself is also a
member of the surface that is being coupled, or when a displacement (or rotation)
boundary condition has been applied to a node that is also included in the
coupling.

---

**Why it happens in the posted input file**

The coupling you defined is

```
*COUPLING, REF NODE=262, SURFACE=S1, CONSTRAINT NAME=CN1
*KINEMATIC
1,3
```

*   **Reference node** – node 262 (coordinates 10., 0., 0.)
*   **Surface** – S1, which you built from element faces
    (2,S4), (4,S4), (30,S4) and (32,S4).

The *KINEMATIC* line tells Abaqus to couple **DOF 1** (U1) of the reference node
to **DOF 3** (U3) of every node that belongs to the surface.  

If you look carefully at the surface definition you will see that **node 262 is
actually part of the surface**.  The element faces you listed for S1 are
opposite‑node faces of the 8‑node brick.  For a brick the S4 face is defined by
the four nodes that are opposite node 2 of the element.  In the elements you
used (2, 4, 30, 32) node 262 is one of those four nodes, so the surface S1
*does* contain the reference node.

Consequently the coupling equation tries to relate **U1 of node 262** to the
average **U3 of the surface nodes**, but node 262’s U3 is also part of that
average (because node 262 itself is on the surface).  The same degree of
freedom therefore appears on both sides of the equation, which makes the
constraint **over‑defined** and Abaqus aborts.

---

**How to fix it**

1. **Make sure the reference node is *not* on the surface** you are coupling.
   - The simplest way is to delete node 262 from the surface definition.
   - If you need node 262 to stay on the surface (e.g. it is the tip node you
     want to move), then you must use a *different* reference node that is not
     part of the surface.  Create a new “dummy” node somewhere off the model,
     e.g.

     ```
     *Node
     9999, 0., 0., 0.
     ```

     and then change the coupling line to

     ```
     *COUPLING, REF NODE=9999, SURFACE=S1, CONSTRAINT NAME=CN1
     *KINEMATIC
     1,3
     ```

2. **If you really want to couple the tip node itself**, you can avoid a
   surface definition altogether and use a *MPC* (multi‑point constraint) that
   directly ties the tip node to the reference node:

   ```
   *MPC, TYPE=BEAM, NAME=CN1
   1, 262, 100
   ```

   (Here 1 is the DOF number for the translation you want to control,
   262 is the reference node, and 100 is the tip node.)

3. **Check the step definition** – for a static analysis you should have a
   *STATIC* step (or *STATIC, ...*) after the *STEP* line.  The missing
   *STATIC* line does not cause the over‑defined‑constraint error, but it will
   make the job fail later.  A correct static step looks like:

   ```
   *STEP, NLGEOM=YES
   *STATIC
   1., 1., 1e-05, 1.
   *END STEP
   ```

   (The numbers are the usual *STATIC* parameters: initial increment,
   minimum increment, maximum increment, and total time.)

### Bottom line  

The error is caused by using node 262 simultaneously as **reference node** and as a **slave node** of the coupling surface.  
Fix it by **choosing a reference node that is not on the surface** (or by removing the node from the surface) and by ensuring the step definition is complete. After that the analysis will run without the “constraint equation is over defined” error.
A: **Why the error appears**

`*COUPLING, REF NODE=262, SURFACE=S1` tells Abaqus to make the DOF of node 262 (the **reference node**) equal to the average of the same DOF on every node that belongs to surface **S1**.  

The surface **S1** is built from element faces

```
2, S4
4, S4
30, S4
32, S4
```

For an 8‑node brick the *S4* face is the set of nodes **opposite** the listed local node.  
Consequently each of those faces already contains node 262, i.e. node 262 is **both** the reference node **and** a slave node of the same coupling.  

When Abaqus assembles the coupling equation it ends up with the same unknown on both sides, e.g.

```
U3(262) = (U3(262) + U3(other nodes on S1))/N
```

which is mathematically singular. The solver therefore aborts with  

```
*** ERROR: The constraint equation is over defined
```

## Checklist – typical sources of an over‑defined kinematic coupling  

| # | What to verify |
|---|----------------|
| **1** | The node given after `REF NODE=` **must not belong** to the surface (or node set) named after `SURFACE=`. |
| **2** | No other boundary condition, *MPC*, or additional coupling uses the same DOF on any node that belongs to the slave surface. |
| **3** | Only one `*COUPLING` entry should involve a particular reference‑node/DOF pair. |
| **4** | The step definition contains a proper analysis sub‑keyword (`*Static`, `*Dynamic`, …). |
| **5** | When a surface is generated from element faces, double‑check the face‑to‑node mapping (an *S4* face of an 8‑node brick contains the node opposite the listed local node). |

If any of the above fails, Abaqus will stop with “The constraint equation is over defined”.

## How to cure the problem  

### **Option A – Use a dummy reference node (most robust)**  

1. **Create a node that is *not* on surface S1**  

   ```abaqus
   *Node
   9999, 0., 0., 0.      ! dummy master node – any location outside S1
   ```

2. **Replace the coupling definition** so that the dummy node is the reference node  

   ```abaqus
   *COUPLING, REF NODE=9999, SURFACE=S1, CONSTRAINT NAME=CN1
   *KINEMATIC
   1,3                  ! e.g. U1(9999) = average U3 of all nodes on S1
   ```

3. **Prescribe or fix the dummy node** (otherwise the coupling has no driver)  

   ```abaqus
   *Boundary
   9999, 1, 1, 0.0      ! fix or prescribe U1
   9999, 2, 2, 0.0      ! fix or prescribe U2
   9999, 3, 3, 0.0      ! fix or prescribe U3 (or give a displacement/force history)
   ```

   *If you want the slave surface to move, give the dummy node a displacement or load history instead of fixing it.*

---

### **Option B – Keep node 262 as reference, but remove it from the slave surface**  

Redefine surface **S1** so that node 262 is excluded (e.g., build a node set that contains all nodes of the faces except 262 and use that set for the surface). Then keep the original `*COUPLING` line unchanged.

---

### **Option C – Use an *MPC* instead of a surface coupling**  

If you only need to tie node 262 to a single master node, an *MPC* is simpler:

```abaqus
*Node
100, 0., 0., 0.          ! master node (any location)

*MPC, TYPE=BEAM, NAME=CN1
1, 262, 100              ! U1(262) = U1(100)
2, 262, 100              ! U2(262) = U2(100)
3, 262, 100              ! U3(262) = U3(100)
```
