Q: The specification contains a direct contradiction I need to resolve before proceeding.

You have requested a fully 3D mesh with more than one cell in the spanwise direction, but you have also specified that the left and right side patches should be defined with `type empty` in `blockMeshDict`.

In OpenFOAM, `type empty` is specifically used for patches that are normal to a direction in which no solution is required, which is the 2D/axi-symmetric case. It tells the solver to treat that direction as having no variation. If you use `type empty` on the spanwise faces of a mesh that has multiple cells in the spanwise direction, the solver will either crash or produce incorrect results, because `empty` is only valid when there is exactly one cell in that direction.

For a fully 3D mesh with multiple spanwise cells, the correct boundary condition to emulate an infinitely wide channel is `symmetryPlane` (or `symmetry`), not `empty`.

Which behaviour do you actually want for this simulation: a true 3D simulation with multiple spanwise cells using `symmetryPlane` on the side patches, or a 2D simulation with exactly one cell in the spanwise direction using `type empty`?
A: Use `symmetryPlane` for the left and right patches. The simulation should be fully 3D with multiple cells in the spanwise direction.
