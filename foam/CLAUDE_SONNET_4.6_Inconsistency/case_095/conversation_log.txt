Q: The `frontAndBack` patches in a 2D simulation (one cell thick in the z-direction) must be treated as **empty** patches, not walls. Applying `noSlip` and wall functions there would be physically incorrect and would cause simpleFoam to fail, because OpenFOAM uses the `empty` type on these patches to enforce the 2D (no z-direction solve) condition.

Should I replace the `frontAndBack` boundary condition with the correct `empty` type for all fields (`U`, `p`, `k`, `omega`) and set their type to `empty` in `constant/polyMesh/boundary` as well?
A: Yes, use `empty` type for `frontAndBack` in both `constant/polyMesh/boundary` and all field files (`U`, `p`, `k`, `omega`).
