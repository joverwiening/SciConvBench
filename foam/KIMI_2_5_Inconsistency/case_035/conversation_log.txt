Q: I need to check for a contradiction in your boundary condition setup.

The 'frontAndBack' patches are defined as 'symmetryPlane' in the mesh boundary file, but you've specified 'type wall' with fixed value in the velocity field file. These are incompatible—symmetryPlane patches must use symmetryPlane boundary conditions in the field files.

Which boundary condition type do you want to use for 'frontAndBack': symmetryPlane (for 2D simulation with symmetric behavior) or wall (which would require changing the patch type in the boundary file)?
A: Use **empty** for the 'frontAndBack' patches in both the boundary file and the 0/U file. This is the standard approach for 2D simulations with a one-cell-thick mesh.

If you prefer to use **symmetryPlane**, then it must be used consistently in both the boundary file and the 0/U file. Do not mix patch types and boundary conditions.
