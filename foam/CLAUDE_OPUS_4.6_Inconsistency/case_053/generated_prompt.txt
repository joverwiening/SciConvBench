The simulation uses the interFoam solver from OpenFOAM to model the mixing of water and a non-Newtonian (Bingham plastic) sludge in a 2D tank.

The tank is 0.5 m wide and 1.0 m tall, representing a reasonable lab-scale mixing vessel.

The simulation is two-dimensional, achieved by using a single-cell thickness in the z-direction with empty boundary conditions on the front and back patches.

The two phases are water and sludge.

The phases entry in transportProperties is: phases (water sludge);

The water phase is configured as follows in transportProperties:
transportModel Newtonian;
nu 1e-6;
rho 1000;

The sludge phase is configured as follows in transportProperties:
transportModel BinghamPlastic;
rho 1500;
tau0 15;
mu0 0.1;
muInf 0.01;

The surface tension between the two phases is sigma 0.07.

The initial condition places sludge in the bottom half of the tank (0 to 0.5 m height) and water in the top half (0.5 to 1.0 m height), set via the alpha.sludge field using setFieldsDict.

Mixing is driven by gravity acting downward at 9.81 m/s^2, causing a gravity-driven Rayleigh-Taylor-like instability and density-driven flow between the heavier sludge and lighter water.

All four physical walls (left, right, bottom, top) use no-slip velocity boundary conditions (fixedValue uniform (0 0 0)) and zeroGradient for pressure.

The top wall uses a totalPressure or fixedFluxPressure condition for p_rgh to allow proper pressure referencing in the enclosed tank.

The front and back patches are set to the empty type for the 2D simulation.

The alpha.sludge field uses zeroGradient on all walls and empty on front and back.

The simulation duration is 5 seconds.

The time step is controlled by an adjustable time step with an initial deltaT of 1e-4 s and a maximum Courant number of 0.5 to ensure stability with the VOF method.

The maximum deltaT is 1e-3 s.

The mesh resolution is 100 cells in the x-direction and 200 cells in the y-direction, giving uniform 5 mm cells, generated using blockMesh.

The z-direction uses 1 cell spanning from 0 to 0.005 m.

Write results every 0.05 seconds for post-processing.

The gravity vector is set in the constant/g file as (0 -9.81 0).

The fvSchemes file uses Gauss linear for gradient schemes, Gauss vanLeer for divergence schemes related to alpha, Gauss linearUpwind for velocity divergence terms, and Gauss linear corrected for Laplacian schemes.

The fvSolution file uses PIMPLE with 3 outer correctors and 2 non-orthogonal correctors, GAMG solver for pressure, and smoothSolver with GaussSeidel for velocity and alpha fields.
